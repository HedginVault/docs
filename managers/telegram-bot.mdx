The Telegram bot lets managers review vaults, swap tokens, manage liquidity, trade perpetuals, and change settings from chat.

<Warning>
The bot holds your wallet's private key on its server and signs for you. Its operator can access that key. A manager's vault authority cannot be transferred if the key is exposed.

Telegram chats are not end-to-end encrypted. Import only a dedicated manager wallet whose risk you accept. Export a backup of any wallet the bot creates before relying on it.
</Warning>

## Get started

1. Open a private chat with the bot. Groups are not supported.
2. Send `/wallet` and import a dedicated wallet or create one.
3. Add an API key issued for that wallet. Ask Hedgin for the required access if the wallet cannot create a key through the console.
4. Send `/vaults` to open your vaults.

A new wallet must be whitelisted before it can create vaults. Each wallet needs its own API key.

## Use commands

| Command | Purpose |
| --- | --- |
| `/start`, `/vaults` | Open your vault list. |
| `/wallet` | Create, import, export, or switch wallets. |
| `/holdings <vault>` | Review holdings and exposure. |
| `/strategies <vault>` | Review trading strategies. |
| `/nav <vault>` | Review valuations. |
| `/requests <vault>` | Review pending deposits and withdrawals. |
| `/history <vault>` | Review closed strategies. |
| `/phoenix <vault>` | Open perpetual trading. |
| `/settings <vault>` | Review fees, limits, and status. |
| `/cancel` | Stop entering a form value. |
| `/help` | Open help in chat. |

Use a vault address, its list number, or its name for `<vault>`.

## Trade and manage

Choose a vault, select an action, fill in the form, and review the confirmation screen. Amounts accept a value such as `1.5`, a percentage such as `25%`, or `max`.

The bot uses the active wallet and its API key. Check both before confirming. Available actions depend on the key's permissions.

The venue guides explain the trading choices and restrictions.

- [Jupiter swaps](/managers/jupiter-swaps).
- [Meteora DLMM positions](/managers/meteora-dlmm).
- [Phoenix perpetuals](/managers/phoenix-perps).

For a first vault created through the bot, use USDC. Custom deposit tokens require an existing vault the key can access. Vault creation also requires a key permitted to create vaults, rather than one restricted to an existing vault.

## Protect access and handle interruptions

Keep a private backup of every wallet key. Removing a wallet deletes the bot's copy of its key and API key. Funds remain on chain, but you need your own key to retain access.

After a bot restart, send `/start` for fresh buttons. If an action has an unknown result, check its transaction link before repeating it. Earlier completed steps remain if a later step fails.

For automation that keeps the signing key in your own process, use the [TypeScript SDK](/sdk/overview).
